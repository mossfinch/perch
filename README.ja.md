タスクを Claude Code や codex に渡します。あとは Perch が見ています。青は agent が動いている、
黄色はあなたを待っている、緑は終わった、という意味です。承認を見逃さないために端末を見張り続ける
必要はありません。視線を外して大丈夫です。

カードを開くと、Perch はさらに次のことをします。

- プロジェクトごとに、agent が実行中・承認待ち・完了のどれなのかを表示する
- その週の受け渡しのリズムから、自分の集中の状態を見えるようにする
- 待っているあいだに、図解とビートの付いた 30 秒エクササイズを出し、終わったらローカルに 1 件記録する

待ち時間はどうせ発生しています。Perch はそれが画面を見つめる時間になってしまわないようにするだけです。

![開いたカード：小鳥の足元にある 1 週間の記録、今日の切り替わる数値、フローの波形、そしてビートと Start ボタンの付いたエクササイズ](perch-card.png)

## Perch を作った理由

coding agent のおかげで自分の手を動かす時間は減りましたが、代わりに新しい注意のリズムが生まれました。
タスクを渡し、待ち、戻って確認し、承認して、また次のラウンドを始める。1 回の待ち時間は数十秒か
数分ですが、agent がいつ戻ってくるか分からないので、端末を見つめながらスマホや別のタブに
気を取られる、ということが起きがちです。

Perch が守りたいものは 2 つです。

- **集中**：agent の結果を受け取って次のラウンドを始めるまでの速さから、この協働が途切れずに
  続いているかを判定し、1 日と 1 週間の集中のリズムを表示します。
- **健康**：もともとある待ち時間を短い回復に変えます。図解があるので動き方を調べるところから
  始めなくてよく、ビートがあるのでタイマーを別に見る必要もありません。そのとおりに終えたら
  次のラウンドに戻れます。

人に成績をつけるためのものではありません。これまで見えなかった集中のリズムと、つい無駄になりがちな
回復の機会を見えるようにするためのものです。いつ協働がなめらかだったのか、いつ集中のリズムが
ゆるんだのか、そして細切れの待ち時間を本当に自分の回復に使えたのか。

## agent を代わりに見張る

Claude Code と codex の hook が、実行中・承認待ち・完了といったライフサイクルの状態を Perch に渡します。

畳んでいるときは、ノッチの両側に状態ごとの件数が出ます。葉っぱの色は、いま一番あなたの注意が
必要な状態の色になります。

ノッチにカーソルを合わせるとカードが開きます。プロジェクトごとに状態を示すドットが 1 つあり、
プロジェクト名は順番に切り替わって表示されます。どれか 1 つでも承認待ちのプロジェクトがあれば、
名前はそこで止まり、あなたが処理するまで動きません。

![畳んだ状態の Perch：1 枚の葉っぱと、状態ごとの件数](perch-status-key.png)

## 小鳥の足元にある 1 週間

カードの 1 行目は月曜から日曜までの止まり木で、小鳥は今日の位置に立っています。まだ来ていない日は
グレーのまま。終わった日と進行中の日は、同じコーラル色の 5 段階の濃淡で、Perch が計測した
受け渡しのリズムを表します。

止まり木の右側には、次の 3 種類が順番に表示されます。

- **in flow 2h 37m**：直近の受け渡しが詰まっていると Perch が判定した時間の合計。
- **agents ran 5h 10m**：少なくとも 1 つの agent が動いていた実時間。複数の agent が並行していても
  1 回分としてしか数えません。
- 直近に完了したプロジェクト名。

この 2 つの時間はあえて分けてあります。agent が動いていることと、あなたがそれと速いテンポで
やり取りしていることは別だからです。どちらも労働時間の合計でもありません。

止まり木の特定の日にカーソルを合わせると、右側の表示がその日の段階、`in flow` の時間、
`agents ran` の時間に切り替わります。

![水曜日にカーソルを止めたところ：その日の段階と 2 つの時間](perch-week-hover.png)

### Perch が言う「in flow」

Perch は `in flow` で、agent との協働のなかで集中が続いていた時間を見積もります。ものさしにするのは
直近の受け渡しの速さです。つまり、**agent が 1 ラウンドを終えたあと、あなたがすぐ次のラウンドを
始めているか。そしてその速い受け渡しが直近も続いているか。**

Perch は画面の内容も、プロンプトも、応答本文も、最前面の app も読みません。見るのは agent の
ライフサイクルイベントだけです。おかげでこの数値はローカルに閉じ、境界もはっきりしています。
その代わり、読む・考える・決めるという時間は受け渡しを生まないので、カウントされません。

つまりこれは**集中の状態を推定している**のであって、注意力を直接読み取っているわけではありません。
読んでいる時間、考えている時間、決めている時間も同じくらい集中しているかもしれませんが、
受け渡しが発生しないぶん少なく見積もられ、数値が実際の集中時間より低く出ることがあります。
この数値は、人と agent のやり取りがどれだけ途切れずに続いたかを見るためのものであって、
仕事の質や能力、成果を評価するためのものではありません。その日に表示できる `in flow` の時間が
ないときは、`—` と表示されます。

日ごとの段階は、その日に計測された `in flow` の時間だけで決まります。

| 段階 | その日に計測された時間 |
| --- | --- |
| 1/5 | 1 時間未満 |
| 2/5 | 1〜2 時間 |
| 3/5 | 2〜4 時間 |
| 4/5 | 4〜6 時間 |
| 5/5 | 6 時間以上 |

2 行目の波形は、同じ判定のリアルタイム版です。`in flow` と判定されているあいだは、明るく、速く
動きます。いまの判定が違うと思ったら波形をクリックしてください。ある日の段階が違うと思ったら、
止まり木のその日をクリックすると、段階が 1 → 5 → 1 の順に進みます。この修正で変わるのは表示されて
いる判定や段階だけで、元のイベントが書き換わることも、すでに計測された時間が変わることも
ありません。

## 30 秒エクササイズ

coding agent と長く付き合っていると、注意はタスクのあいだを行き来する一方で、体はずっと同じ姿勢の
ままになりがちです。Perch は、待ち時間にいちばんおろそかになる首・肩・目のケアを 30 秒の
エクササイズに分けました。図解が動き方を示し、ビートが切り替えのタイミングを教えてくれるので、
いまの作業環境を離れてチュートリアルやタイマーを探し直す必要はありません。

終わると、Perch はローカルのエクササイズ記録に 1 件残します。「今日も立って体を動かすつもりだった」
ではなく、実際に何をやったかをあとから見られます。

![3 つのエクササイズの図解：首の側面のストレッチ、僧帽筋のリラックス、目のまわりのマッサージ](perch-care-moves.png)

Perch は医療機器ではなく、医学的なアドバイスや健康上の効果を約束するものでもありません。動かして
痛みが出たら中止し、専門家に相談してください。

## ローカルデータとプライバシー

Perch にアカウントは要りません。テレメトリもありません。**このパッケージのどこにも
ネットワーク通信のコードはありません**。agent と app のあいだは App Group コンテナ内の
Unix domain socket で通信しますが、`AF_UNIX` ソケットはそもそもネットワークに到達できません
——**これはコードの行儀ではなく、OS が強制していることです**。

Perch はプロンプトや応答本文を保存しません。保存するのは次のものです。

- agent の実行中・承認待ち・完了イベント
- agent を動かしたプロジェクトのフルパス
- エクササイズの実施記録
- リアルタイム判定や日ごとの段階に対して、あなたが行った修正

これらのデータはすべてこの Mac の中に残ります。プロジェクトのフルパスもプライバシー情報です。
残したくない場合は、下の「アンインストールとデータの削除」を見てください。

<details>
<summary>履歴の再構築がなぜあるのか、そして何を読むのか</summary>

app のインストールスクリプトは `~/.perch/bin/perch-reconcile` を入れます。これは LaunchAgent が
ログイン時と 30 分ごとに実行します。Codex の rollout と Claude のセッション記録からライフサイクルの
メタデータを読み、hook がときどき取りこぼす開始イベントと終了イベントを補います。

スキャン結果の作業キャッシュは `~/.perch/reconciliation` にあり、いつ削除してもかまいません。
通常の LaunchAgent は Team 付きの App Group に直接書き込めないため、Perch app が既存のローカル
socket 経由でライフサイクルの行と検証済みの派生結果をやり取りし、そのうえでコンテナへアトミックに
書き込みます。どちらの方向にもプロンプトや応答本文は流れませんし、サンドボックス内の app が
ホームディレクトリ全体の読み取り権限を得ることもありません。

</details>

## 対応している agent

### Claude Code

`install-island-hooks.py` を実行すれば接続できます。

### codex

完了の状態は codex の notify スクリプト経由、実行中と承認待ちの状態は `~/.codex/hooks.json` 経由で
届きます。codex は `/hooks` パネルで信頼した hook しか実行しません。緑の件数は変わるのに青と黄色が
まったく動かない場合、たいていはその信頼をまだ許可していません。

## インストール

必要なものは次のとおりです。

- **macOS 15 以降**
- Swift 6 ツールチェーンを含む **Xcode**。Apple Developer アカウントは不要で、app はこの Mac の
  ad-hoc 署名を使います
- **python3**。Xcode を入れていれば `/usr/bin/python3` が使えます
- `/Applications` に書き込める管理者アカウント。`sudo` は最後まで使いません
- **Node 22**。テストを実行したいときだけ必要です

```bash
python3 install-island-app.py          # ビルド → /Applications/Perch.app → ログイン時に起動
python3 install-island-hooks.py        # Claude Code に接続
python3 install-codex-island-hooks.py  # codex に接続。プロンプトが出たら hook を一度だけ信頼する
```

初回起動時に、macOS が 1 度だけ許可を求めます。
**システム設定 → プライバシーとセキュリティ → このまま開く**。

app のインストールスクリプトは、`/Applications/Perch.app` の場所にある別の app を上書きしません。
古い Perch を見つけたときも、削除ではなく脇へどけます。インストールの最後には、Perch の socket に
実際に 1 度接続して、app のプロセスがあるだけでなく、イベントをちゃんと受け取れる状態かどうかを
確認します。

<details>
<summary>hook のインストールスクリプトが何を変えるのか</summary>

hook のインストールスクリプトは、まず元の設定の隣にタイムスタンプ付きの `.perch-backup-*` バックアップ
を残し、そのうえで Perch の項目だけを追加します。他の hook を並べ替えたり、削除したり、書き換えたり
はしません。他人の hook が Perch と同じグループに入っていても同じです。

書き込む前に、スクリプトは外部の項目がすべて読み取った時点とバイト単位で同じで、位置も変わって
いないことを確認します。途中で誰かが設定を変更していた場合は、中止して元のファイルをそのまま
残します。最後の置き換えはアトミックなリネームで行うので、書きかけの設定ファイルが残ることは
ありません。

</details>

## アンインストールとデータの削除

app、ログイン時の起動項目、履歴の再構築ツールをアンインストールします。

```bash
launchctl bootout gui/$UID/io.github.mossfinch.perch
rm ~/Library/LaunchAgents/io.github.mossfinch.perch.plist
launchctl bootout gui/$UID/io.github.mossfinch.perch.reconcile
rm ~/Library/LaunchAgents/io.github.mossfinch.perch.reconcile.plist
rm ~/.perch/bin/perch-reconcile
rm -rf ~/.perch/reconciliation
rm -rf /Applications/Perch.app
```

hook を入れている場合は、次の場所からも Perch の項目を消してください。

- `~/.claude/settings.json` と `~/.codex/hooks.json`：コマンドに `bridge.sock` を含む Perch の項目を
  削除するか、隣にある `.perch-backup-*` バックアップを戻します
- `~/.codex/hooks/codex-notify-sound.sh`：`# --- Perch` で始まる完了サウンドのブロックを削除します。
  このファイルにも専用の `.perch-backup-*` バックアップがあるので、ここでも復元できます

Perch が保存したローカルデータをすべて削除します。

```bash
rm -rf ~/Library/Group\ Containers/group.io.github.mossfinch.perch
```

このディレクトリには、エクササイズの記録 `care-ledger.json`、agent の生イベント
`agent-events/*.jsonl`、そして `reconciliation/` 以下の再構築できる派生履歴とヘルス状態が
入っています。Codex と Claude がそれぞれ自分で保存している元の履歴は各自のディレクトリに残り、
このコマンドでは消えません。

## App Group 名を変更する場合

コンテナのパスは App Group 名に連動して変わるため、古いエクササイズ記録が自動で新しいコンテナに
現れることはありません。明示的に移行してください。

```bash
python3 install-island-app.py --migrate-from <以前の-app-group-id>
```

インストールスクリプトはコピーするだけで、削除はしません。すでにある記録の上書きは拒否し、
シンボリックリンクや読み取れない記録ファイルも受け付けません。新しいコンテナへの書き込みは
アトミックに行います。

## 開発

```bash
xcodebuild -project Perch.xcodeproj -scheme Perch build   # または Xcode で開く
node --test tests/island.test.js                          # テストを実行
```

`perch-package.json` は、公開パッケージに含めるファイルの境界を定める唯一のマニフェストです。
テストに含まれるプライバシーガードは、このマニフェストが対象とするファイルをすべてスキャンします。
